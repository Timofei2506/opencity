# OpenCity

Оpen-world экшен от третьего лица в духе классических GTA: процедурный город, угон автомобилей,
стрельба, полиция и уровень розыска, день/ночь, трафик и пешеходы.

Проект сделан так, чтобы **собираться автоматически в GitHub Actions** и **не требовать ни одного
импортированного ассета**: геометрия, PBR-текстуры, материалы, звук и UI генерируются кодом.

| | |
|---|---|
| Движок | Unity **2022.3.20f1** (LTS) |
| Пайплайн рендера | Built-in RP, Linear color space, soft shadows, 4 shadow cascades |
| Платформы сборки | Windows x64, Linux x64 (матрица CI) |
| Язык | C# (25 скриптов, ~7000 строк) |
| Внешние ассеты | нет: 50 PBR-текстур генерируются `Tools/gen_textures.py`, звук — синтез в рантайме |

## 1. Что уже реализовано

### Мир
* Процедурный город **7×7 кварталов** (~480 × 480 м): сетка улиц, тротуары с бордюрами,
  дорожная разметка (осевая, полосы, парковочные «тики», зебры, стоп-линии).
* Здания: 4 стиля фасадов (бетон, кирпич, панель, стеклянный curtain wall), цокольные этажи
  с витринами и маркизами, парапеты, уступы у высоток, крыши с кондиционерами, водяными баками,
  антеннами и рекламными щитами.
* Парк с фонтаном, скамейками и деревьями; парковки с припаркованными машинами.
* Уличная мебель: фонари (со реальным светом по бюджету), светофоры с фазами,
  автобусные остановки, гидранты, урны, люки.
* Цикл дня и ночи (10 минут на сутки): кастомный шейдер неба (градиент, солнце, облака, звёзды,
  луна), trilight-ambient, туман, изменение цвета света, включение эмиссии окон и фонарей.

### Игрок и бой
* Контроллер от третьего лица: ходьба/бег/спринт, прыжок, прицеливание, камера с коллизией,
  переключение на погоню за машиной.
* Процедурный человекоподобный риг (общий для игрока, пешеходов и полиции) с анимацией
  ходьбы/бега/прицеливания и падения.
* Оружие: пистолет, карабин, дробовик — хитскан, разброс, отдача, перезарядка, хедшоты,
  трассеры, вспышки, искры, кровь.
* Здоровье и броня, респавн в «больнице» со списанием денег.

### Машины
* Физика на 4 `WheelCollider`: крутящий момент, 5-ступенчатая АКПП, зависимый от скорости
  руль, анти-крен, даунфорс, ручник (дрифт), визг шин, звук двигателя с pitch по оборотам.
* Процедурный кузов: лофтинг по сечениям (3 типа — седан, купе, фургон), стёкла, стойки,
  зеркала, бамперы, решётка, диски, фары со спот-лампами, задние фонари.
* Угон: подойти и нажать **F** — машина переходит из трафика под управление игрока.

### ИИ
* Трафик: движение по правым полосам, безье-повороты на перекрёстках, соблюдение светофоров,
  торможение перед препятствиями, восстановление при «застревании».
* Пешеходы: обход квартала по тротуару, паника при стрельбе/преступлении, дроп денег.
* Полиция: диспетчер спавнит патрульных по уровню розыска, погоня, стрельба при прямой
  видимости; на 3+ звёздах выезжают патрульные машины с сиреной и преследованием.

### Мета-игры
* Уровень розыска 0–5 звёзд с затуханием.
* Работа «доставка»: жёлтый маркер → доехать до точки за время → деньги.
* HUD: миникарта (вторая камера → RenderTexture), здоровье/броня, деньги, звёзды, оружие/патроны,
  часы, цель, прицел, вспышка урона, спидометр.
* Сохранение/загрузка (JSON в `Application.persistentDataPath`): позиция, деньги, розыск, время
  суток, здоровье/броня, патроны, активная миссия.
* Пауза (Esc) с меню, экран управления (F1).

## 3. Сборка в GitHub Actions

Сборка выполняется на официальных Docker-образах Unity (`unityci/editor:ubuntu-2022.3.20f1-*`),
которые workflow запускает напрямую через `docker run`. В одном контейнере происходит активация
лицензии и сборка плеера вызовом `Assets/Editor/BuildScript.cs` (`-executeMethod`).

### 3.1. Обязательные секреты репозитория

`Settings → Secrets and variables → Actions → New repository secret`

| Секрет | Обязательно | Описание |
|---|---|---|
| `UNITY_EMAIL` | да | e-mail аккаунта Unity ID |
| `UNITY_PASSWORD` | да | пароль Unity ID |
| `UNITY_TOTP_KEY` | при 2FA | секрет аутентификатора (если на аккаунте включена двухфакторная аутентификация) |
| `UNITY_SERIAL` | только Plus/Pro | серийный номер подписки |

Файл лицензии в секретах **не нужен**. Перед сборкой CI получает Personal-место (seat) штатным
клиентом лицензирования Unity:

```bash
Unity.Licensing.Client --activate-all --include-personal \
    --username "$UNITY_EMAIL" --password "$UNITY_PASSWORD"
```

> Ручная активация через https://license.unity3d.com/manual больше не используется: Unity оставила
> офлайн-активацию `.alf → .ulf` только для Enterprise, для бесплатных мест она отключена.

Проверить активацию отдельно: `Actions → Unity license → Run workflow`
(артефакт `unity-license` содержит лог и состояние лицензии).

### 3.2. Запуск

* Автоматически: `git push` в `main` (изменения в `.md` и `Tools/` сборку не триггерят).
* Вручную: `Actions → Build game → Run workflow`.

Основная цель сборки — **StandaloneWindows64**. Артефакт `OpenCity-Windows64` (хранится 30 дней)
содержит `OpenCity.exe`, `UnityPlayer.dll` и папку `OpenCity_Data`; лог сборки — в артефакте
`logs-StandaloneWindows64`.

Сборка `StandaloneLinux64` вынесена в отдельный workflow `Build Linux (experimental)`:
на образе `unityci/editor:ubuntu-2022.3.20f1-*` сборка Linux-плеера уходит в бесконечное
ожидание (Unity не реагирует на SIGTERM, поэтому в workflow стоит watchdog с `pkill -9`
и сохранением лога). Windows-плеер собирается штатно.

Быстрая проверка компиляции без сборки плеера — workflow `Compile check` (~5 минут).

Первая сборка занимает ~15–25 минут (импорт проекта), повторные — ~5–10 минут благодаря кешу `Library`.
Репозиторий публичный, поэтому минуты GitHub Actions не тарифицируются.

### 3.3. Локальная сборка

Меню `OpenCity → Build → Windows 64-bit` / `Linux 64-bit` собирает плеер в `build/` тем же
скриптом, что использует CI. Для интерактивной проверки откройте папку проекта в Unity Hub (версия **2022.3.20f1**), откройте `Assets/Scenes/Main.unity`,
нажмите Play. Меню `OpenCity → Apply project settings` повторно применяет настройки
(цветовое пространство, шейдеры в Always Included, сцена в Build Settings).

## 4. Структура проекта

```
Assets/
  Scenes/Main.unity            сцена с единственным объектом GameBootstrap
  Scripts/
    Core/      GameBootstrap, GameManager, SaveSystem, InputHub, MaterialLibrary (+Go, GameConst)
    World/     MeshKit (+MeshBatcher), CityGenerator, BuildingFactory/PropFactory,
               RoadNetwork (+TrafficLight), DayNightCycle
    Characters/ PlayerController, CameraDirector, PlayerCombat, Health, HumanoidRig
    Vehicles/  VehicleController, CarFactory
    AI/        TrafficCar, Pedestrian (+CashPickup), PoliceDispatch (+PoliceOfficer)
    UI/        Hud (+Minimap)
    FX/        FxFactory (billboard particles, трассеры, взрывы)
    Audio/     ProceduralAudio (синтез всех звуков)
    Game/      MissionSystem
  Editor/      ProjectSetup (настройки проекта, always-included shaders), TextureImportSettings
  Shaders/     SkyboxSky.shader
  Resources/Textures/          50 сгенерированных PBR-карт (albedo/normal/металл-гладкость/эмиссия)
Tools/gen_textures.py          генератор текстур (детерминированный, бесшовный)
.github/workflows/build.yml    сборка Windows + Linux
.github/workflows/unity-license.yml  получение файла активации
```

### Ключевые архитектурные решения

* **Всё процедурное.** Ни одного импортированного `.fbx`, `.png` извне, ни одного префаба:
  сцена содержит один объект, остальное строится в `GameBootstrap.Awake()`.
* **Vertex batching.** `MeshBatcher` сливает тысячи мелких мешей в несколько чанков по материалам
  (лимит 60k вершин на чанк) — город рисуется десятками draw call'ов.
* **Единый набор материалов.** `MaterialLibrary` кэширует материалы, поэтому батчинг работает,
  а ночная эмиссия окон включается одной функцией `SetNightFactor()`.
* **Свет по бюджету.** Реальные источники света включаются только у 14 ближайших фонарей —
  остальные светятся эмиссивным материалом.
* **Шейдеры в сборке.** Материалы создаются в рантайме через `Shader.Find`, поэтому
  `ProjectSetup` принудительно добавляет нужные шейдеры в *Always Included Shaders*
  (иначе в билде они вырежутся).
* **Текстуры.** `Assets/Editor/TextureImportSettings` — `AssetPostprocessor`, который по суффиксу
  имени (`_n`, `_mg`, `_e`) выставляет корректные настройки импорта, так что «сырые» PNG работают
  как PBR-карты без ручной настройки.

## 5. Настройка и тюнинг

| Хочу | Где |
|---|---|
| Размер города | `GameConst.BlocksX/BlocksZ`, `BlockSize`, `RoadWidth` |
| Длину суток | `GameConst.DayLengthSeconds` |
| Характер машины | `VehicleController` (MaxMotorTorque, MaxSteerAngle, GearSpeeds) |

| Скорость ИИ/плотность | `CityGenerator.SpawnTraffic(14)`, `SpawnPedestrians(34)` |
| Цвета/материалы | `MaterialLibrary` |
| Разрешение миникарты | `Minimap.Init()` (RenderTexture 384²) |
| Генерацию мира | поле `Seed` на объекте `GameBootstrap` (0 = случайный город) |

## 6. Известные ограничения / что дальше

* Персонажи — процедурные меши без скиннинга (анимация по суставам, а не по костям).
  Следующий шаг: импорт glTF/FBX-моделей и `SkinnedMeshRenderer`.
* Нет NavMesh: пешеходы/полиция используют собственный steering и raycast-обход препятствий.
* Нет пост-обработки (bloom/SSAO) — добавляется пакетом `com.unity.postprocessing`
  или переходом на URP/HDRP.
* Дорогая часть — `WheelCollider`; при увеличении числа машин стоит переводить трафик на
  кинематическую модель без коллайдеров колёс.
* Идеи: ограбления, магазины, метро, погода, полицейские погони с блокпостами,
  мультиплеер (Netcode).

## 7. Диагностика

| Симптом | Причина / решение |
|---|---|
| Розовые объекты в билде | шейдер вырезан — проверьте `OpenCity → Apply project settings` |
| Сборка падает на активации лицензии | неверные `UNITY_EMAIL`/`UNITY_PASSWORD`, включённая 2FA без `UNITY_TOTP_KEY`, либо для Plus/Pro не задан `UNITY_SERIAL` |
| `Failed to write file: .../Resources/unity_builtin_extra` + `Assertion failed on expression: 'm_LockCount == 0'` | в Always Included Shaders попал внутренний шейдер Unity (`Hidden/InternalErrorShader`, `GUI/Text Shader`) с `HideFlags.DontSave` — уберите его из списка в `Assets/Editor/ProjectSetup.cs` |
| «Unsupported Unity version» в CI | нет Docker-образа `unityci/editor` под эту версию; выставьте существующий тег в `build.yml` и `ProjectSettings/ProjectVersion.txt` |
| Тёмная сцена | не хватает памяти на shadow cascades — уменьшите `QualitySettings.shadowCascades` |
| Нет звука | не должно быть: звук синтезируется; проверьте, что `ProceduralAudio.Engine` не null в логе |
